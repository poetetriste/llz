## 2. Главный корпус

- Файл: `benchmarks/corpus.txt`
- Размер: 1 251 867 байт
- SHA-256: `87c32bcab75083d2191c6592218748c7cff492e98cf5ce336ea7669088c6a5dc`
- Источник: plain-text extracts восьми статей русской Википедии, 2026-11-05
- Токены ruGPT-3: 155 823
- Модель: `sberbank-ai/rugpt3large_based_on_gpt2`
- Профиль: fp16, CUDA, `torch.compile`, scale `2^28`, block 2 048
- Payload: 77 590 Б, 16,1343858744684 : 1
- LLZ2: 77 654 Б, 16,1210884178536 : 1
- Payload density: 0,495835420216365 бит/байт исходника
- CRC32: `1ba4c55c`

### Исправление метаданных 0.1.0

`verify_big.py` выставлял квантователь `2^28`, но при завершении ошибочно
передавал в `pack()` число `16`. Специальный decode-скрипт игнорировал поле
контейнера и поэтому скрывал дефект; обычный CLI использовал бы `2^16` и получил
CRC mismatch.

- исходный локальный LLZ2 SHA-256:
  `9952a5e53a402c0493cf89f6398f68cdb6fd229a59148052a532d7c3be014c4b`;
- исправленный LLZ2 SHA-256:
  `32b5b5041b9cce3895e421a41c65f2f98ad639df99c5a05f88bccd8622f44c44`.

Исправлены только четыре байта `scale_bits` (`16` → `28`). Payload побайтово
не изменён. Новый `verify_big.py` записывает фактический scale и применяет scale
из контейнера при decode. Явное переопределение оставлено только для миграции
известного дефектного артефакта.

## 3. Самосгенерированный крайний случай

Файл: `benchmarks/self_generated_degenerate.txt`, 39 277 байт, SHA-256
`adc66198463e24069c01406522ef072fe41c3735d9a7af6eb9dfe7e6dc30eed2`.

Генерация `rugpt3small`, temperature 0,8, top-p 0,9, выродилась в повторение
предложения «Если мы говорим о том, что мы знаем о существовании интеллекта…».
Поэтому результат характеризует самопредсказуемость зацикленной генерации, а не
русский текст в целом.

| Слой учёта | Байт | Степень |
|---|---:|---:|
| entropy estimate | 115,10 эквивалентных | 341,255 : 1 |
| arithmetic payload | 147 | 267,190 : 1 |
| LLZ3 container | 324 | 121,225 : 1 |
| bz2 -9 | 961 | 40,87 : 1 |
| xz -9e | 992 | 39,59 : 1 |
| gzip -9 | 1 100 | 35,71 : 1 |

Причины разницы между 341× и 267×:

1. entropy script суммировал вещественные `-log2(p)`, а кодек использует
   целочисленный квантователь с минимальным счётчиком 1;
2. оценочный script применял схему скользящих окон, а реальный кодек сбрасывает
   контекст блоками;
3. арифметический поток имеет конечный overhead завершения.

LLZ3 дополнительно содержит 177 байт заголовка: модель, immutable commit,
вычислительный профиль, версии библиотек, размеры и CRC32.

Контрольный архив: `benchmarks/self_generated_degenerate.llz3`, SHA-256
`57672c33e2113434e3a267af32466d13fd151670e6044a1f9afff709836acd63`.

## 4. Исправления надёжности

### Critical/high

- Исправлено несоответствие scale в `verify_big.py`.
- Исправлен кэш моделей: раньше смена model id в одном процессе могла вернуть
  уже загруженные веса первой модели.
- `assert` больше не используется для проверки внешних параметров scale и magic;
  проверки сохраняются под `python -O`.
- LLZ3 валидирует длины, profile flags и размер payload до загрузки модели.
- CLI по умолчанию не записывает результат при CRC mismatch.
- HTTP decode возвращает 422 и не выдаёт повреждённые байты при CRC mismatch.
- HTTP body и число декодируемых токенов ограничены конфигурируемыми лимитами.
- Checkpoint большого прогона связан с SHA-256 исходника, моделью, scale,
  командой и числом токенов; stale checkpoint отклоняется.
- Checkpoint сохраняется атомарно. Он остаётся доверенным локальным pickle.

### Provenance

LLZ3 хранит:

- immutable Hugging Face revision;
- dtype/device/compile profile и block;
- Python, PyTorch, Transformers и NumPy versions;
- payload length, token count и CRC32.

LLZ1/LLZ2 читаются для обратной совместимости, но не имеют полной provenance.

## 5. Выполненные тесты

На аудируемой машине:

- Python 3.12.16
- torch 2.14.1+cu126
- transformers 5.22.1
- NumPy 2.5.4
- RTX 3060 12 ГБ

Результаты:

- 23 model-free unit tests arithmetic coder/LLZ3/CLI/quantizer/cache/artifacts — PASS;
- statement coverage пакета по объединённому прогону — 80%;
- 400 randomized arithmetic-coder trials и дополнительные stress cases — PASS;
- scale `2^16..2^28`, invalid scale — PASS;
- 18 модельных Unicode/edge cases — PASS;
- два последовательных encode дают одинаковый payload — PASS;
- повреждённый payload обнаруживается CRC32 — PASS;
- self-generated LLZ3: 4 767 токенов, byte-exact, CRC32 — PASS;
- portable fp64/CPU archive на 162 токенах — CRC32 PASS;
- Python compileall — PASS;
- `pip check` — PASS.

Длительный повторный decode полного 155 823-токенного GPU-архива после миграции
заголовка не выполнялся в рамках этого аудита: payload уже проходил полный круг
при исходном измерении, а миграция не меняла ни одного байта payload. Для новой
независимой машины такой прогон всё равно остаётся обязательным.

## 7. Ограничения публичных формулировок

Разрешено заявлять:

- «16,13× payload на конкретном 1,25-МБ корпусе русской Википедии»;
- «267,19× реальный lossless payload на зацикленном тексте самой модели»;
- «341,26× entropy estimate на том же искусственном файле»;
- «кросс-машинный профиль прошёл на двух конкретных Windows/AMD-машинах».

Нельзя заявлять без нового доказательства:

- «341× реальный архив»;
- «16× на русском тексте вообще»;
- «универсально переносимый между любыми машинами архив»;
- мировой рекорд без единого корпуса, правил учёта декомпрессора и независимой
  верификации;
- криптографическую целостность на основании CRC32.
