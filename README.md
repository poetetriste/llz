# llz — проверяемое lossless-сжатие текста языковой моделью

`llz` кодирует UTF-8-текст через распределения следующего токена causal LLM и
целочисленный арифметический кодер. Декодирование воспроизводит исходные байты;
каждый публикуемый практический результат проходит encode → decode, побайтовое
сравнение и CRC32.

Релиз 0.2.0 устраняет ошибки метаданных 0.1.0, добавляет LLZ3 с точной ревизией
модели и версиями вычислительного стека, жёсткую валидацию контейнера и полностью
воспроизводимые benchmark-артефакты.

## Подтверждённые результаты

### Обычный текст: русская Википедия

Корпус: восемь статей, 1 251 867 байт, SHA-256
`87c32bcab75083d2191c6592218748c7cff492e98cf5ce336ea7669088c6a5dc`.

Модель: `sberbank-ai/rugpt3large_based_on_gpt2`, fp16, CUDA,
`torch.compile`, scale `2^28`.

| Величина | Результат |
|---|---:|
| Токены | 155 823 |
| Арифметический payload | 77 590 Б |
| Степень по payload | **16,134 : 1** |
| Контейнер LLZ2 | 77 654 Б |
| Степень по контейнеру | **16,121 : 1** |
| Информационная плотность payload | 0,4958 бит/байт исходника |
| Проверка | побайтово, CRC32 `1ba4c55c` |

Точный корпус и исправленный контрольный архив находятся в `benchmarks/`.
В локальном артефакте 0.1.0 поле scale ошибочно содержало `16`, хотя payload
был записан с `2^28`. В приложенном архиве изменены только четыре байта этого
поля; 77 590 байт payload остались неизменными. Оба SHA-256 записаны в
`benchmarks/manifest.json`.

Сравнение на том же файле:

| Метод | Размер | Степень |
|---|---:|---:|
| gzip -9 | 312 170 Б | 4,01 : 1 |
| brotli -q11 | 240 478 Б | 5,21 : 1 |
| xz -9e | 240 116 Б | 5,21 : 1 |
| bz2 -9 | 213 062 Б | 5,88 : 1 |
| **llz payload** | **77 590 Б** | **16,13 : 1** |

Модель не входит в размер архива. Такое сравнение имеет смысл только в сценарии,
где одинаковые веса уже доступны кодеру и декодеру.

### Искусственный самосгенерированный текст: где появляется 341×

Файл `benchmarks/self_generated_degenerate.txt` содержит 39 277 байт и 4 767
токенов. Он был сгенерирован самой `rugpt3small`, после чего генерация выродилась
в многократное повторение одной фразы. Это специально зафиксированный крайний
случай, а не репрезентативный русский текст.

| Метрика | Размер/степень | Round-trip |
|---|---:|---:|
| Сумма `-log2(p)` по исходной кривой | 920,77 бит = **341,26 : 1** | нет, оценка |
| Реальный арифметический payload | 147 Б = **267,19 : 1** | **да** |
| Полный LLZ3 с provenance | 324 Б = **121,23 : 1** | **да** |
| bz2 -9 | 961 Б = 40,87 : 1 | да |
| xz -9e | 992 Б = 39,59 : 1 | да |
| gzip -9 | 1 100 Б = 35,71 : 1 | да |

Итоговая формулировка: **341,26× — подтверждённая энтропийная оценка на
зацикленном тексте самой модели; подтверждённый lossless payload — 267,19×,
полный самодостаточный по метаданным LLZ3-контейнер — 121,23×.**

Проверка:

```powershell
$env:HF_HUB_OFFLINE = "1"       # если модель уже в кеше
$env:LLZ_DTYPE = "fp16"
$env:LLZ_COMPILE = "1"
python -m benchmarks.verify_self_generated
```

Скрипт создаёт архив, декодирует его публичным API, проверяет байты и CRC32 и
записывает `benchmarks/self_generated_result.json`.

## Как работает кодек

1. Токенизатор превращает текст в токены.
2. LLM выдаёт распределение следующего токена.
3. Квантователь назначает каждому токену как минимум один целочисленный счётчик.
   Сумма счётчиков не превышает `SCALE`; она не обязана быть ровно `SCALE`.
4. 30-битный арифметический кодер записывает фактический токен.
5. Декодер повторяет тот же пошаговый путь с тем же профилем вычислений.

Контекст сбрасывается блоками по `n_positions` модели (для ruGPT-3 — 2 048
токенов). Батчевый teacher-forcing encoder оставлен только как эксперимент:
его floating-point след может отличаться от пошагового декодера.

## Контейнер LLZ3

LLZ3 хранит:

- id и immutable revision модели Hugging Face;
- scale, dtype, device/compile и размер блока;
- версии Python, PyTorch, Transformers и NumPy;
- CRC32 исходных байтов, число токенов и точный размер payload.

LLZ1 и LLZ2 продолжают читаться. LLZ3 отклоняет обрезанные заголовки,
недопустимые profile-флаги и несовпадение заявленного размера payload до загрузки
модели. CRC32 защищает от случайного повреждения, но не является криптографической
аутентификацией против умышленной подмены.

## Установка и CLI

```bash
pip install .

llz encode letter_original.txt -o letter.llz
llz inspect letter.llz
llz decode letter.llz -o letter.restored.txt
```

По умолчанию используется `rugpt3small`. Главный результат 16,13× получен с
`rugpt3large`, поэтому модель всегда следует указывать явно при его повторении:

```bash
llz bench benchmarks/corpus.txt \
  --model sberbank-ai/rugpt3large_based_on_gpt2
```

Для полного GPU-профиля нужны:

```text
LLZ_DTYPE=fp16
LLZ_COMPILE=1
```

## Профили воспроизводимости

GPU fp16 + `torch.compile` обеспечивает скорость, но архив следует декодировать
на том же программно-аппаратном профиле. LLZ3 предупреждает о несовпадении
версий; окончательный арбитр — CRC32.

Портируемый CPU-профиль был проверен между двумя Windows/AMD-машинами на 162 и
2 968 токенах:

```text
MKL_CBWR=COMPATIBLE
ATEN_CPU_CAPABILITY=avx2
OMP_NUM_THREADS=4
LLZ_DTYPE=fp64
LLZ_DEVICE=cpu
scale=2^18
torch=2.14.1
transformers=5.22.1
numpy=2.5.4
```

Это демонстрация на двух конфигурациях, не универсальная математическая гарантия.
Перед переносом на новую машину необходимо запустить `cross_test/`.

## Проверки

Быстрые, без загрузки модели:

```bash
python -m unittest discover -s tests -v
python test_llz.py A
python -O test_llz.py A
```

Модельные краевые случаи:

```bash
python test_llz.py B 0 99
```

Большой корпус с доверенными локальными checkpoint-файлами:

```bash
set LLZ_MODEL=sberbank-ai/rugpt3large_based_on_gpt2
set LLZ_DTYPE=fp16
set LLZ_COMPILE=1
python verify_big.py encode benchmarks/corpus.txt 1251867 enc.pkl 270
python verify_big.py decode benchmarks/corpus.txt 1251867 dec.pkl 270
```

Checkpoint использует `pickle` и предназначен только для собственных локальных
файлов. Не открывайте чужие checkpoint-файлы.

## Ограничения

- Кодек принимает только UTF-8-текст, не произвольные бинарные данные.
- Степень сильно зависит от языка, домена и возможного пересечения с обучающими
  данными модели.
- ~100 токенов/с на `rugpt3large` — это холодное хранение и дорогие каналы, не
  замена потоковым архиваторам.
- Без точных весов, токенизатора и совместимого вычислительного профиля архив не
  декодируется.
- Размер модели не включён в приведённые коэффициенты.
- Для долгосрочного хранения необходимо отдельно сохранять веса и их лицензию.
