# llz — lossless-сжатие текста языковой моделью + арифметическое кодирование

> Верифицируемый бенчмарк: **16,13 : 1** на корпусе русской википедии (1 251 867 байт),
> полный круг encode→decode с **побайтовым совпадением и CRC32**.
> Для сравнения на том же файле: gzip 4,01×, brotli 5,21×, xz 5,21×, bz2 5,88×.

Дата замеров: 2026-11-05. Лицензия: MIT.

---

## 1. Что это

Текст кодируется не напрямую, а как последовательность «удивлений» языковой
модели: LLM предсказывает распределение следующего токена, арифметический кодер
записывает только информацию, необходимую для выбора фактического токена из
этого распределения. Декодер с **той же моделью и тем же fp-профилем**
воспроизводит те же распределения и восстанавливает текст побайтово.

Ключевое отличие от опубликованных LLM-компрессоров (LLMZip, FineZip):
**каждая заявленная цифра подтверждена полным кругом** — декодированный поток
побайтово сравнивается с оригиналом, CRC32 хранится в контейнере архива.

## 2. Проверенные результаты

### 2.1. Главный бенчмарк (полный корпус)

- Файл: `corpus.txt`, русская википедия (выборка), **1 251 867 байт UTF-8**
- Модель: `sberbank-ai/rugpt3large_based_on_gpt2` (760 М параметров)
- Профиль: fp16, CUDA, torch.compile (default mode)
- Токенов: 155 822
- **Результат: 77 590 байт payload (77 654 с контейнером) = 16,13 : 1**
- Decode: 155 822/155 822 токенов, **побайтовое совпадение: ДА, CRC32: OK**

### 2.2. Против классики (тот же файл, та же машина)

| Метод | Размер, байт | Степень | llz лучше в |
|---|---|---|---|
| gzip -9 | 312 170 | 4,01 : 1 | 4,02× |
| brotli -q11 | 240 478 | 5,21 : 1 | 3,10× |
| xz -9e | 240 116 | 5,21 : 1 | 3,10× |
| bz2 -9 | 213 062 | 5,88 : 1 | 2,74× |
| **llz (rugpt3large)** | **77 590** | **16,13 : 1** | — |

### 2.3. Кривая по моделям (срез 110 000 байт того же корпуса)

Все строки — полный круг с побайтовой проверкой.

| Модель | Параметры | Сжато | Степень | Скорость decode |
|---|---|---|---|---|
| rugpt3small | 117 М | 7 256 Б | 15,16× | 277 ток/с |
| rugpt3medium | 355 М | 6 307 Б | 17,44× | ~148 ток/с |
| rugpt3large | 760 М | 6 134 Б | 17,93× | ~102 ток/с |
| mGPT-1,3B | 1,3 Б | 14 681 Б | 7,49× | ~69 ток/с |

Замечание: срез 110 КБ «легче» среднего по корпусу (17,93× против 16,13×
на полном файле). Для сравнений использовать цифру полного корпуса.

### 2.4. Маленький текст (краевой случай)

`letter_original.txt`, 1 109 байт → 141 байт (7,87 : 1), rugpt3small.
162 токена. Побайтово, CRC32 OK.

### 2.5. Скорость

RTX 3060 12 ГБ, torch 2.14.1+cu126, transformers 5.22:

- CPU fp32: ~29 ток/с
- GPU fp16: ~104 ток/с
- GPU fp16 + torch.compile: **~277 ток/с** (rugpt3small), ~100 ток/с (rugpt3large)
- Полный круг 1,25 МБ на rugpt3large: ~50 минут (encode ≈ 26 мин + decode ≈ 26 мин
  при ~100 ток/с; 155 822 токена)
- Прогрев torch.compile: ~40 с на запуск процесса

## 3. Как воспроизвести

```bash
pip install .
# модель скачается с HuggingFace при первом запуске

# быстрый тест (письмо, ~10 с на GPU)
python verify_corpora.py letter_original.txt 100000

# полный бенчмарк (1,25 МБ, ~45 мин на RTX 3060, чекпоинты каждые 4,5 мин)
set LLZ_DTYPE=fp16
set LLZ_COMPILE=1
set LLZ_MODEL=sberbank-ai/rugpt3large_based_on_gpt2
python verify_big.py encode corpus.txt 1251867 enc.pkl 270   # повторять до "ГОТОВО"
python verify_big.py decode corpus.txt 1251867 dec.pkl 270   # повторять до "ГОТОВО"
```

Требования для fp16+compile профиля: CUDA-совместимая GPU, MSVC Build Tools
(cl.exe нужен inductor'у на Windows). Без compile всё работает, медленнее.

## 4. Устройство кодека

- **Арифметический кодер**: 30 бит точности, Python-int (переполнение
  исключено), ренормализация с pending-битами.
- **Квантователь вероятностей**: SCALE = 2^28 > размера словаря (50 257) —
  у каждого токена счётчик ≥ 1, нулевые вероятности исключены.
- **Контекст**: KV-cache, сброс блоками по 2048 токенов (n_positions),
  зеркально в кодере и декодере: кодер сбрасывает при i % 2048 == 0,
  декодер — при (i-1) % 2048 == 0 (перед подачей токена).
- **Контейнер LLZ2** (бинарный):
  `magic | model_id_len u8 | model_id | scale u32 | dtype u8 | device u8 |
   block u32 | crc32 u32 | n_tokens u64 | payload`
  - dtype: 0=fp32, 1=fp16, 2=fp64; device: 0=cpu, 1=cuda, 2=cuda+compile
- **fp-профили**: CPU / CUDA / CUDA+compile дают разные битовые распределения.
  Архив декодируется только на профиле записи; при несовпадении выводится
  предупреждение, окончательный арбитр — CRC32.
- **Портируемый профиль (кросс-машинный, проверен 2026-11-06 на 162 и 2 968
  токенах между двумя разными ПК, CRC32 OK):**
  `LLZ_DTYPE=fp64` + `LLZ_DEVICE=cpu` + `MKL_CBWR=COMPATIBLE` +
  `ATEN_CPU_CAPABILITY=avx2` + `OMP_NUM_THREADS=4` + scale 2^18 +
  пиннинг torch 2.14.1 / transformers 5.22.1 / numpy 2.5.4.
  Проверено на двух разных ПК: архив, записанный на одном, побайтово
  декодирован на другом. Это не гарантия для произвольных конфигураций —
  перед использованием на новой паре машин прогоняйте стенд `cross_test/`.
  Цена: +2,8% к размеру, ~5 ток/с на CPU. Рецепт и стенд — в `cross_test/`.

## 5. Честные ограничения и отрицательные результаты

1. **Степень зависит от домена.** 16× — на вики-тексте, который модель
   частично «знает» из обучения. На тексте вне домена модели результат хуже,
   на случайных данных — хуже классики. Это общее свойство всех LLM-компрессоров.
2. **Скорость.** ~100 ток/с — это инструмент холодного хранения и узких каналов,
   а не замена gzip.
3. **Модель = часть словаря.** Без той же модели и fp-профиля архив не читается.
4. **LoRA-под-документ (FineZip) не окупается < 10 МБ.** Замерено тремя
   конфигами (r=8/4/2): адаптер даже в 2-битной записи в 10–18 раз больше
   экономии потока. Лучший выигрыш энтропии: −28,8% (r=8, 800 шагов).
5. **Мультиязычные модели слабее для русского** (mGPT: 7,49× против 17,93×).
6. **Батчевый encode (teacher forcing) ломает арифметический кодер** —
   fp-дрейф между батчевым и пошаговым ядрами: расхождение ±50–769 счётчиков
   из 2^28. В продукте используется только пошаговый путь.
7. **torch.compile mode="reduce-overhead"** сегфолтится на StaticCache
   (transformers 5.22). Рабочий режим — default, без CUDA graphs.
8. **Оценка 341× на самосгенерированном тексте** — экстраполяция по кривой
   энтропии, НЕ подтверждена round-trip. Не использовать в заявлениях.

## 6. Позиционирование (честно)

- Абсолютная лига (Hutter Prize / LTCB, enwik9): действующий присуждённый
  рекорд — fx2-cmix-T, 100 424 672 байт ≈ 0,803 бит/байт (трансформер 6 М
  параметров, дообученный на enwik9; присуждён 2026-09-30). Поданные заявки
  (cmix-neif и др., ~92–96 МБ) уже ниже и ждут верификации. Мы в этой лиге не
  участвуем — там английский корпус и зачёт размера декомпрессора.
- LLM-лига: LLMZip+AC ([arXiv:2306.04050](https://arxiv.org/abs/2306.04050)) —
  0,7101 бит/символ на 1 МБ срезе text8 (LLaMA-7B); авторы оговаривают, что
  text8 построен из википедии, входившей в обучение LLaMA, — результат
  оптимистичен. FineZip ([arXiv:2409.17141](https://arxiv.org/abs/2409.17141))
  сообщает: LLMZip на Llama3-8B — 10 МБ за ~9,5 суток; их подход — ~4 ч.
  Мы: 0,496 бит/байт на русской вики (760 М модель, 1,25 МБ за ~50 мин) — с той
  же оговоркой: rugpt3 обучалась в том числе на русской википедии. Корпуса,
  языки и условия разные — прямое сравнение некорректно.
- Для русского языка публичного верифицируемого lossless-бенчмарка
  LLM-сжатия раньше не существовало — эта таблица первая.

## 7. Структура репозитория

```
llz/                пакет
  arith_coder.py    арифметический кодер
  codec_lib.py      модель, квантователь, KV-cache путь
  cli.py            encode/decode/bench (entry point `llz`)
  server.py         HTTP-сервис (entry point `llz-server`)
test_llz.py         стресс-тесты кодера + краевые случаи + детерминизм
test_server.py      e2e тест HTTP-сервиса
verify_corpora.py   полный круг на файле (быстрый)
verify_big.py       полный круг на больших файлах с чекпоинтами
benchmark.py        таблица llz vs gzip/brotli/xz/bz2
REPORT.md           полный отчёт о замерах
```

Тесты: `python test_llz.py A` (кодер, секунды) · `python test_llz.py B 0 99`
(краевые случаи с моделью). Все зелёные на момент релиза.
